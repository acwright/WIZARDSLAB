2. THE DESCRIPTION, PASTE-READY
-------------------------------------------------------------------------------

Paste the block between the rules into itch's description editor. The lines
marked >>H<< are headings — style them as such after pasting and delete the
marker. Bullets are the ones marked with a dash.

- - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -

Potions rain down from the shelves of a wizard's laboratory in vials of six
colours. Line up three or more of a colour — horizontally, vertically or
diagonally — and they react and vanish, dropping whatever sat above them into
new arrangements.

Among the potions fall the arcane reagents: fireballs, bolts, bombs, stars and
prisms. Placed well, they set each other off, and a single piece can unravel
half the board.

Wizards Lab is a 16 KB cartridge for three 8-bit machines — the Commodore 64,
the Commodore VIC-20 and the AC6502 — written in 6502 assembly. Same playfield,
same tiles, same timing, on all three.

This is a cartridge, not a browser game — but it is one file per machine and
it loads like anything else. Drag the .crt onto VICE, or drop it on the SD card
of a C64 Ultimate, an Ultimate II+ or a VIC-20 Final Expansion 3 and pick it
from the file browser. VIC-20 owners with an sd2iec or a 1541 want the .prg
instead — same game, loaded as a program. Raw ROM images are in the same
download for anyone burning an EPROM.

>>H<< The one rule worth knowing

Tiles match on colour. The glyph on a tile decides what happens when it clears.

A red potion, a red fireball and a red star are all "red" — so every reagent is
aimed exactly like the potion it resembles, and you choose when to set it off.

- Fireball — destroys every tile of its own colour, board wide
- Bolt — clears its whole row and column, up to 21 cells
- Bomb — clears the 3 × 3 around it
- Star — doubles the whole cascade's score, up to ×8
- Prism — wildcard, matches any colour

A reagent caught in another reagent's blast goes off too. That is where the
game lives.

>>H<< Controls

Rotate — joystick up, or W, or cursor up
Move — joystick left and right, or A and D, or the cursor keys
Soft drop — joystick down, or S, or cursor down
Rotate back — fire, or Q, or SPACE
Pause — P
Start — fire, or SPACE, or RETURN

Joysticks are Atari 2600 compatible — port 2 on the C64.

>>H<< What is in the download

run/ — load these. One file per machine, the load address carried inside it.

- WizardsLab-C64.crt — Commodore 64
- WizardsLab-VIC20.crt — VIC-20, both blocks in the one file
- WizardsLab-VIC20.prg — VIC-20 from a disk drive, see below
- WizardsLab-AC6502.crt — AC6502

eprom/ — burn these. Raw ROM images, named for their size and load address, for
a 27C128, a pair of 27C64s or a 28C256.

>>H<< Running it

Drag the .crt onto a running VICE window, or:

Commodore 64 — x64sc -cartcrt WizardsLab-C64.crt

VIC-20 — xvic -cartcrt WizardsLab-VIC20.crt

AC6502 — 6502 run --cart WizardsLab-AC6502.crt

On a C64 Ultimate, an Ultimate II+ or a VIC-20 Final Expansion 3, copy run/ to
the SD card and pick the .crt from the file browser.

VIC-20 FROM A DISK DRIVE — take WizardsLab-VIC20.prg. A .crt only means
something to hardware that emulates cartridge ROM; an sd2iec, the SD side of a
Penultimate Cartridge or a real 1541 is a disk drive, and a cartridge has to be
ROM in the address space at reset. The .prg is the same 16 KB as a program that
copies itself into place and starts. SET THE MEMORY TO 32K OR 35K FIRST — the
two blocks have to have somewhere to land, and that is the one thing that
catches people out.

One file per machine, including the VIC-20. Its 16 KB is two 8 KB blocks at
different addresses — BLK5 at $A000 holds the code, BLK3 at $6000 the artwork —
and both are inside the one .crt. They are separate files only in eprom/, where
they are two separate chips.

x64sc and xvic are VICE — https://vice-emu.sourceforge.io/
The AC6502 emulator — https://github.com/acwright/6502-EMULATOR

>>H<< How it was made

One source tree, three cartridges. Everything the game does is shared code;
the only things that differ are four constants and seven routines behind a
platform contract, so no game logic anywhere knows which machine it is on.

The VIC-20 set the shape of it. Its 22 columns are the playfield all three
machines draw, its eight hi-res colours capped the palette at six potions plus
white, and its ~1 KB of usable RAM is what the whole 557-byte memory layout was
designed against. Designing for the tightest machine first is why the other two
needed no compromises.

Source, and the full design document — every rule, scoring table and level
speed — at https://github.com/acwright/WIZARDSLAB

MIT licensed.

    Font .................... whatever itch's default sans is

4. THE IMAGES
-------------------------------------------------------------------------------

All of them in images/, all generated by `make itch` (tools/itch.py). The
cover and the reagent card are drawn by blitting data/tileset.bin through
data/tilecolor-c64.inc — the same two files the C64 cartridge includes — so
the letters on the cover are the game's letters and the six potion colours are
the six the machine actually draws. Redraw a tile, `make artwork`, `make itch`,
and the cover changes with it. There is no second copy of the artwork.

  cover.png                      630 × 500
      The cover image field. 630 × 500 is exactly what itch asks for, so it is
      used uncropped. Title, one glyph of every kind in one of every colour,
      and the three machines. Legible at the 315 × 250 the browse pages use,
      which is what the type size is set by.

  screenshot-1-c64-play.png     1008 × 864      C64, a real game 32 pieces in
  screenshot-2-c64-title.png    1008 × 864      C64, title
  screenshot-3-vic20-play.png   1152 × 800      VIC-20, the same game
  screenshot-4-vic20-title.png  1152 × 800      VIC-20, title

      The four committed screenshots from docs/, recentred, aspect-corrected
      and upscaled. Nearest neighbour and integer factors, so 8 × 8 tiles still
      look like 8 × 8 tiles. The two play shots are the same dealt game on both
      machines.

      They are RECENTRED because what VICE writes is its whole visible frame,
      and the machine's screen does not sit in the middle of it — the VIC-20's
      is up and to the left with the border eating the rest. So the frame here
      is taken from the character grid outward: the grid, plus exactly one cell
      of border on all four sides. Centred by construction, on both machines.

      They are ASPECT-CORRECTED because neither machine has square pixels, and
      the VIC-20's are the further off. Its dot clock is 4 × the system clock
      and the C64's is 8 ×, so a VIC-20 pixel is exactly twice as wide as a C64
      pixel — and a C64 pixel is itself 0.75 as wide as it is tall on a 4:3
      set. Both are scaled 3 × across and 4 × down, which lands each machine on
      its own true aspect and leaves the two at a common scale: an 8 × 8 cell
      comes out 24 × 32 on the C64 and 48 × 32 on the VIC-20. That is the real
      difference between the two screens — 22 fat columns against 40 thin ones
      — and it is the thing a pair of square-pixel shots hides.

      There are no AC6502 shots. Its emulator writes no PNG.

  reagent-card.png               960 × 640
      Not a screenshot — the five reagents and what each one does, set in the
      game's own font and colours. It goes in the gallery third, after the two
      play shots: the reagents are the reason to play and a still of a full
      well does not explain them. Reads fine as the page's only text image if
      someone never scrolls to the description.

  background.png                 96 × 96
      The page background, in the theme editor. A seamless brick — the game's
      own margin tile — knocked back 55% toward black so it is texture behind
      the text rather than a wall in front of it. Tiles in both axes at any
      page size.

5. THE DOWNLOAD
-------------------------------------------------------------------------------

    dist/WizardsLab-cartridges-v1.0.0.zip                      35 KB

        run/WizardsLab-C64.crt            .crt container, 16K at $8000
        run/WizardsLab-VIC20.crt          .crt container, both blocks
        run/WizardsLab-AC6502.crt         raw 32K, the AC6502's own convention
        eprom/WizardsLab-C64-16k-8000.bin
        eprom/WizardsLab-VIC20-blk5-8k-a000.bin
        eprom/WizardsLab-VIC20-blk3-8k-6000.bin
        eprom/WizardsLab-AC6502-32k-8000.bin
        README.txt                        loading it, burning it, controls,
                                          and the rules
        LICENSE.txt                       MIT

    TWO DIRECTORIES, BECAUSE A CARTRIDGE IMAGE AND AN EPROM IMAGE ARE NOT THE
    SAME FILE. What the linker writes is raw — the bytes that go on the chip,
    nothing around them — which is right for a programmer and wrong for
    everyone else, because nothing in a raw image says where in the address map
    it belongs. VICE will not take one by drag and drop and an Ultimate II+
    will not list it. The .crt files in run/ carry the load address inside
    them, and the VIC-20's carries both of its blocks, so every machine is one
    file to load.

    Rebuild it against the current cartridges with `make dist`, or under
    another version with `make VERSION=v1.1.0 dist`. It is not committed —
    every file in it already is. dist/ also holds the same tree unzipped, if
    you would rather upload the files loose.

    THE VERSION IN THE FILENAME IS THE GIT TAG. v1.0.0 here is the tag v1.0.0
    is the GitHub release v1.0.0, so a zip somebody downloaded a year ago can
    be traced back to the commit that built it, and the two download pages
    cannot quietly drift apart. Bump all three together or none of them; the
    default lives in tools/itch.py.

    The README inside is written for someone who downloaded a zip and has
    never seen the repository, so it repeats the emulator commands, the
    two-file VIC-20 rule, the raw-versus-container .crt warning, and the
    reagents. That repetition is the point: the zip has to stand alone.

6. BEFORE YOU HIT PUBLISH
-------------------------------------------------------------------------------

  [ ] `make itch`, which builds the cartridges and the download before the
      images, so the zip holds what you mean to ship rather than whatever was
      last built. It boots both .crt containers in a headless emulator on the
      way past and stops if either does not come up.
  [ ] Download your own zip off the draft page and run all three from it. A
      zip that was assembled correctly and a zip that plays are not the same
      claim, and the build only checks the two Commodores.
  [ ] Look at the page at phone width. The cover and the reagent card were
      set at sizes that survive it; the screenshots have small type in them
      and will not.
  [ ] Check the GitHub release with the matching tag holds the same four ROMs.
      README.md sends people there rather than here, so the two download
      routes have to agree — same version, same bytes.
  [ ] Post the first devlog: it has run on real hardware. An NTSC VIC-20 with
      its original 6560 and a C64 on a C64 Ultimate, both from the SD card,
      title and play correct. That is the news this page was waiting on and it
      is worth more than a launch post. Say plainly that PAL is untested, and
      that a PAL report is the thing being asked for.
